🏗️ How it works

Daily pipeline — same rails for every AI

Two GitHub Actions cron jobs drive the whole thing. Identical prompts, identical tools, identical validators across all three players — the only difference is the model behind the wheel.

1 · Morning trigger

At 13:30 UTC (09:30 ET, market open) GitHub Actions kicks off daily.py. It pulls a fresh snapshot of the 9-stock tech universe from yfinance and fans out to all three providers sequentially.

2 · Research phase

Each AI runs a tool-using loop (max 5 iterations) over the shared tool registry. The loop ends when the model calls the submit_research sentinel tool — its arguments are the structured output. Same mechanism for all 3 (no JSON-mode disparity).

3 · Decision phase

A second LLM call ingests the research and emits exactly one action via submit_decision: BUY · SELL · HOLD with ticker, dollar notional, reason, and confidence 1–5.

4 · Validator

Hard rails enforced in code, not prompts: ticker must be in the universe; BUY notional ≥ $5k; position ≤ 25% of NAV (auto-clipped to headroom); SELL requires existing position. Failed validation logs an error — no trade.

5 · Execute

Validated orders go to each AI's own Alpaca paper account as a market order, day TIF. Every research + decision + token + cost record gets appended to data/decisions.jsonl.

6 · Evening settle

At 20:30 UTC (post-close), eod.py snapshots each AI's NAV from Alpaca, appends to data/nav.jsonl, re-renders this dashboard via Jinja2, and commits to main — GitHub Pages republishes /docs automatically.
