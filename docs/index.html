🧩 Component reference

What each piece actually does

🌅 daily.py

Morning orchestrator. Pulls the market snapshot from yfinance, then invokes each provider in src/providers.py sequentially. Records the decision, tokens, and cost into decisions.jsonl. Guarded so redundant crons on the same day don't double-trade.

🌇 eod.py

Evening orchestrator. Pulls fresh NAV + open positions from each Alpaca account (marked to consolidated NMS close via yfinance, not the paper feed), snapshots QQQ, fetches every filled order, then rebuilds the static dashboard. Idempotent — safe to re-fire.

🧠 src/prompt.py

The two system prompts every AI sees — RESEARCH_SYSTEM_PROMPT and DECISION_SYSTEM_PROMPT. Identical wording, identical instructions. The only variable in the whole experiment is which model reads them.

🛠 src/tools.py

The 5-function toolkit: get_history, get_news, get_financials, get_analyst_ratings, read_own_trades. Shared JSON schema is exported to all three SDKs (OpenAI, Anthropic, google-genai) so every player calls the exact same functions with the exact same arguments.

🚧 src/decision.py

The central validator. Runs after each AI emits its decision: enforces universe membership, $5k minimum trade, 25%-of-NAV cap per position, and cash availability (patched mid-run when Claude silently used $23k of Alpaca margin — no more accidental leverage).

👥 src/providers.py

The 3-player registry. Each entry pairs an LLM module (llm_chatgpt.py, llm_claude.py, llm_gemini.py) with its own Alpaca paper credentials env vars and a display accent color.

💼 src/broker.py

Thin wrapper on alpaca-py. Submits market orders with DAY time-in-force, reads back the account cash + open positions. Same interface every AI uses — no special sauce per player.

🎨 src/dashboard.py

Jinja2 renderer. Aggregates nav.jsonl + decisions.jsonl + orders.jsonl into the 4-up KPI grid, the total-return chart, the Journal timeline, and the per-AI Recent orders panel. Writes to docs/index.html; GitHub Pages serves it.
